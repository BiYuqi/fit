# T35 — 发送失败可感知 + 重试（前端聊天体验）

**状态**：⬜待办（已确认要做，暂缓执行）

**目标**：消息发送失败时用户有感知、可重试。现状是静默失败——气泡消失、无提示、无重试入口，用户只觉得"发不出消息"。
**依赖**：T16（Chat 页已完成）　**关注文档**：DESIGN_SPEC（聊天气泡）、ARCHITECTURE §本地缓存

## 背景（为什么会有这个任务）

2026-07-03 实际故障：本地后端进程被误杀下线，用户发送"中午吃了千张80克，一个鸡蛋，水煮西兰花200克"，气泡出现后随即消失，无任何反馈，被感知为"聊天框无法发送食物"。排查结论：后端与这句话的解析均无问题，纯粹是请求失败后前端的静默处理放大了故障：

- `frontend/src/stores/chat-store.ts` `send()`：catch 分支把乐观气泡从 messages 里直接移除后 rethrow；
- `frontend/src/app/index.tsx` `handleSend`：`send(text, token).catch(() => {})` 把错误吞掉。

两层叠加 = 任何网络/后端故障都表现为"消息凭空消失"。后端不在线、手机不在同一局域网、Mac IP 变更等都会触发。

## 实现什么效果（微信式）

1. **失败气泡保留**：发送失败时，用户气泡不消失，停留在原位，旁边显示红色感叹号标记（参考微信），可附一行小字"未发送"。
2. **点击重试**：点红色感叹号 → 该气泡重新进入发送中状态（isSending 表现同正常发送，显示 ThinkingBubble），成功后失败标记清除、AI 回复正常追加；再次失败则回到失败态。
3. **可删除**：失败气泡长按（或感叹号旁提供删除入口）可删掉这条未发送消息，避免留着碍眼。
4. **失败气泡不进 SQLite 缓存**：只存在于内存 store（messages 数组，带 `failed: true` 一类标记），不调用 `upsertMessages`——本地缓存只存服务器确认过的消息，防止污染跨端/搜索数据。冷启动后失败气泡丢失可接受（MVP 取舍，写进验收说明即可）。
5. **发送中不允许对同一条重复重试**（防连点造成重复入库）。

## 做什么（指引，不限定实现细节）

- `chat-store.ts`：send() 失败时不再移除 temp 消息，改为打失败标记；新增 `retrySend(tempId)` 与 `removeFailed(tempId)`；重试成功后按现有成功路径替换（移除 temp、写入服务器返回的 messages、更新 summaryCard）。
- `message-item.tsx`（或用户气泡渲染处）：user 气泡支持 failed 态渲染（红色感叹号 + 点击/长按交互）。
- `index.tsx`：handleSend 不再吞错（错误已在 store 内转为 failed 态，无需 throw）。
- 注意 inverted FlatList 下失败气泡的位置保持：后续新消息到来时失败气泡应留在其发送时刻的位置（按现有 messages 数组顺序自然成立）。

## 验收

- 停掉后端 → 发消息：气泡保留 + 红色感叹号，无消失、无崩溃；重启后端 → 点感叹号重试：消息成功入库、AI 回复出现、失败标记消失。
- 重试期间连点感叹号不产生重复记录（后端 food_record 只有一条）。
- 失败气泡可删除；删除后不再出现。
- 失败气泡不写入 SQLite（清空重进 App 后消失属预期）；正常收发路径回归无变化。
- 组件测试按 docs/TESTING.md 规范补：failed 态渲染 + 重试/删除交互。
