# T60 — 省略句追问绑定最近实体：「50克蛋白有多少」不再接错话题

**状态**：✅已完成

**目标**：刚记完/刚弹出份量卡的食物，用户用省略句追问（「50克蛋白有多少啊」「那热量呢」）时，AI 应绑定**最近一轮的话题实体**（刚记录的食物），而不是抓住更早的话题（如十几分钟前的「补蛋白」讨论）。

**依赖**：无强依赖。碰 `ai/ctx.ts`（L0 渲染/prompt）、必要时 `services/resolve-log.ts` / `routes/chat.ts`（reply_summary 质量）。
**关注文档**：`AI_PARSING_SPEC.md`（上下文卡、指代消解）。

## 背景（2026-07-09 真机，账号 outoftoken）

20:01 用户记「全麦面包欧包 自己弄的，有油。热量蛋白如何」→ 弹份量卡并落库（50g/140kcal）。20:02 用户紧跟着问「**50克蛋白有多少啊**」——显然是「50 克欧包含多少蛋白」。AI 却回「50克蛋白质要吃8-9个鸡蛋白或喝700-800ml牛奶」——接到了 19:43 那轮「蛋白不够怎么办」的旧话题上。用户被迫纠正「我说50克欧包的蛋白含量」，又多耗两轮。

当时上下文里**并非没有线索**：L0 recent_turns 含 record 轮的 foods（欧包就在上一轮），pending/份量卡状态也在。问题是 prompt 没有「省略句优先绑定最近实体」的指引，模型被「50克蛋白」的字面 + 更早的蛋白话题带偏。

## 设计要点

### A. 排查上下文供给（结论：供给已够，缺的是指引）
查了 AiTrace.prompt_messages 复盘 2026-07-09 12:02（北京 20:02）那轮：【今日已记录】里 r16 全麦欧包一行齐全（50g/140kcal，当时无 p/f/c，T58 之后已补），【最近对话】里紧挨着两轮就是「记录(全麦欧包/medium)」+「卡片确认(全麦欧包/custom)」。线索完整，模型仍被更早 19:43「蛋白不够怎么办」话题带偏——是纯 prompt 指引缺失，不是供给缺失。T58 已把 L1 记录行补上 p/f/c，进一步加固了这条路径的落地质量。

### B. prompt 增加指代消解规则（已实现）
在 `src/ai/answers.ts` 的 `PERSONA_BASE`（answerChat/answerQuery/answerDiscuss 三个回答函数共享）里加了【追问指代】段：省略主语/宾语的追问默认绑定最近一轮话题实体（【最近对话】刚记录/讨论的食物，其次【今日已记录】最后一条），拿不准就按最近实体回答并点名锚定（「刚记的XX」），只有话题被用户明确澄清或数字明显对不上才回溯更早话题。

### C. eval 用例（已实现）
新增 `eval/cases/ellipsis-followup-entity.yaml`：先聊一轮泛化蛋白话题（制造旧话题干扰源，此时无记录）→ 记录 100g 鸡胸肉（明确克数直接入库）→ 省略句「蛋白有多少啊」（断言回复含「鸡胸肉」，intent 允许 chat/discuss/query）→ 反例「没记录、随便吃呢」验证话题明确切回泛化时不误伤。

## 验收
1. 复现场景：记鸡胸肉 → 问「蛋白有多少啊」→ 回复"刚记的鸡胸肉，100g 里有 **31g** 蛋白"，精确引用记录值（配合 T58）。✅ 真实调用验证通过。
2. 反例不误伤：话题明确换回泛化咨询时，不再机械焊死在刚才那条记录上。✅ eval 用例第 4 轮通过。
3. 新增 eval 用例通过；`npm run eval` 全量跑了 3 轮，仅 chunhuabing / quantifier-delete / meal-batch 各别偶发（每轮失败用例不同），经 git stash 对照确认改动前基线同样偶发——是已知的模型采样抖动（见 MEMORY「eval抖动实锤」），非本次改动引入的回归。
