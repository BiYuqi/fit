# T65 — 显式指令优先级：指令夹在长文本里被 discuss 吞掉（对话精度 R2）

**状态**：✅已完成

**目标**：消息里有明确的修改指令（"改成850卡"），但后面跟着一段说理/论证文字时，整句被判成 `discuss`——AI 只解释、数据一动不动。让"指令 + 长说理"这种形态优先按 `modify` 走。

**依赖**：无。与 T64/T67 都改 `parser.ts` 的 `SYSTEM_PROMPT`，建议按 T64→T65→T67 顺序做，避免同段改动打架。
**关注文档**：`AI_PARSING_SPEC.md` §2（意图路由）、§8（modify）、§9（discuss 的边界）。

## 背景（2026-07-14 真机，账号 outoftoken，已核实 `ai_parse_log.parsed_json`）

用户发（开头就是明确指令，后面是自己手算的论证）：
> "改成850卡。\n\n先拆分食材，分开算均值，再合计总热量\n\n食材基础参考（家常花生油煎鸡胸、普通挂面）\n\n1. 煎鸡胸肉…2. 干挂面…3. 清汤…"

解析结果：`{"intent":"discuss","target":"r9"}`——没有 `action`、没有 `change`，"改成850卡"被完全吞掉。用户被迫 26 秒后简化重发"改成900卡"才生效（数字还从 850 变成 900，因为他放弃讲道理了）。

`npm run audit` 同类还捞出：
- `[2026-07-03] "记录成180kcal"` → `discuss`（T40 上线前一天，同类）
- `[2026-07-03] "不对。我说的是刚才喝的牛奶被你记录成6克蛋白质。改成8克"` → `discuss`（与 T64 同源）

共同形态：**句子里有明确的"动词+数值"指令，但整句语气像在讲道理/纠正，模型就整体判成了"用户在质疑"而不是"用户在下令"。**

## 设计要点

> **定位方式**：本文件的行号只是写作时的快照，**T64–T68 会依次修改同几个文件，行号必然漂移**。一律用搜索定位（文中给出的段落特征字符串），别照行号跳。


### A. discuss 段补排除条款（`SYSTEM_PROMPT`，现约第 33-38 行）

> **⚠️ 改 `SYSTEM_PROMPT` 前必读（跨会话协作约定）**
> T64/T65/T67/T68 是**四个独立会话**（每次 `/clear`）先后修改**同一个** `SYSTEM_PROMPT`，彼此看不见对方加了什么。它现在已有 167+ 行，正是"规则堆叠互相稀释"这个病的病灶——别再无脑往后追加。动手前：
> 1. **通读整个 `SYSTEM_PROMPT`**，确认你要加的规则**是否已有相邻条款可以就地改写**，能改写就不新增。
> 2. 新增时**放进语义相关的既有段落**（意图路由规则进意图段、canonical 规则进 canonical 段），不要在文件末尾堆。
> 3. 加完检查**有没有和已有条款矛盾**（尤其别人刚加的）——发现矛盾就一起改掉，别留两条打架的规则。
> 4. few-shot 用真实原话，**同一个案例只保留一份**，别重复举例。

> 消息中若出现"改成/改为/改到/记成/记录成/算作/调成/调到"+紧跟的具体数值（**不论在句首还是句中，也不论后面跟了多长的解释**），一律优先识别为 `modify.update`，按 §8 规则填 `change`（热量→`calories`、克数→`grams`、宏量素→`protein/fat/carbs`）。
> `discuss` **仅**用于**完全不含改动指令**的纯提问/质疑（"这个热量对吗"、"为什么记成60克"、"这数字怎么来的"）。
> 用户一边给指令一边讲理由，是在**说明为什么要改**，不是在征求意见——照做，不要只解释。

配 few-shot，**原样使用背景里的真实原话**（含后面那段食材拆解），期望输出 `{"intent":"modify","action":"update","target":"<最近被讨论那条的ref>","change":{"calories":850}}`。

### B.（可选增强）把指令信号确定性地喂进上下文
`src/services/explicit-signals.ts`（T63 已落地）的 `extractExplicitSignals(text).instructions` 已经能确定性抽出"改成850"。若 A 的 prompt 规则在 eval 里仍不稳，可在 `compressContext` 或 parser 的 user message 前追加一行【用户明确说了】提示（如 `【明示指令】改成 850`），让模型看到的是**已确认事实**而不是要自己从长文本里挑。

**先只做 A，跑 eval 看够不够**；不够再上 B。别一上来就两个都做——分不清是哪个起的作用，也增加 prompt 噪声。

### C. 不要过度触发（护栏）
"元问题"必须仍然判 chat/discuss，现有规则（`SYSTEM_PROMPT` 约第 42 行）已覆盖，**本任务不得削弱它**：
- "如果我让你改成80大卡，你真的会去改数据库吗" → 仍是 chat/discuss，**不是** modify
- 判据不变：句子在问"你会不会/敢不敢做 X"，而不是直接下令做 X
