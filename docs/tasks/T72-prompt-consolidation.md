## 为什么需要这个任务

这一轮的立项前提是：过去 27 个对话任务**每次真机翻车就往 prompt 里追加一段规则**，导致 `SYSTEM_PROMPT` 涨到 167 行、规则互相稀释（T42 在 T41 上线当天就抓到新回归，即为佐证）。

本轮虽然给每个任务都写了"改 prompt 前先通读、能改写就别新增"的约定，但**四个独立会话各自遵守 ≠ 整体是干净的**：
- A 会话加的规则和 C 会话加的可能表述不一、边界重叠
- few-shot 可能出现同一案例被举了两次
- 某些旧条款可能已被新规则完全覆盖，却没人敢删（因为不知道是不是别人刚加的）

**不做这一步，这轮就只是"更有依据的补丁堆叠"，没有真正跳出原来的循环。**

## 设计要点

### A. 通读收口（核心工作）
完整读一遍 `backend/src/services/parser.ts` 的 `SYSTEM_PROMPT`，逐条过：
1. **重复**：同一件事在两处说 → 合并到语义最相关的那一处。
2. **矛盾**：两条规则对同一输入给出不同指示 → 判断哪条对（以 `eval/cases/` 里的用例为准，用例是真实翻车沉淀），删掉错的。
3. **被取代**：本轮新规则已完全覆盖的旧条款 → 删。特别检查这几处历史补丁是否还需要：
   - T62 加的"日期词 vs 餐次词别混淆"——T68 把 `meal_type` 下沉到 item 级后，这条的表述是否还准确
