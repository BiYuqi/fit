# T58 — 对话营养口径接地：AI 引用记录真值，不再编造系统行为

**状态**：⬜未开始

**目标**：让 AI 在聊天/查询里谈论热量与营养时**引用系统真实数据与真实口径**，杜绝两类事故：① 编造系统行为（如「系统看到米饭默认按生重算」——实际上 T25 后主食 canonical 已是熟形）；② 对已落库的食物自行估营养，报出与记录不一致的数字。

**依赖**：无强依赖。碰 `ai/ctx.ts` / `ai/answers.ts` / `services/parser.ts`（prompt）与 `services/memory.ts`（RecordRef）。
**关注文档**：`AI_PARSING_SPEC.md`（上下文卡）、`FOOD_DB_SPEC.md`（生熟口径，T25）、CLAUDE.md 铁律 1。

## 背景（2026-07-09 真机，账号 outoftoken）

1. **14:43–14:44**：用户说「我说的都是熟的饭」，AI 回「后台系统不是实时学习的——它看到『米饭』默认就按生重算热量，每次说『熟米饭』才能让数字算准，差一倍呢」。**这是幻觉**：库里「米饭（蒸，代表值）」= 116 kcal/100g，本来就是熟值（T25 已完成）。这句假话直接引发用户当晚对欧包记录的生熟爆发。
2. **20:02–20:04**：欧包已落库（后端算出 50g = 140 kcal / 4.6g 蛋白，AI 估算条目 280 kcal/100g，烤后熟重口径），用户问「50克欧包的蛋白含量」，AI 先答「4.5~5g（按市售配方估）」又改口「6.5~7g（按纯全麦粉）」——**记录里明明有 4.6g，AI 看不到，只能瞎估**，三个数字互相打架，用户发「？」表示懵。随后「熟的啊别给我算生的」触发 modify，凭空造出重复食物「全麦欧包（熟的）」（246 kcal/100g，同样 AI 估算）——为一个不存在的错误改账。
3. 根因两条：
   - prompt 里没有任何「系统事实」——AI 不知道库的生熟口径、不知道匹配值即熟值，被追问时就自己编一套。
   - `memory.ts` 的 `RecordRef` 只带 `calories`，**没有蛋白/脂肪/碳水**，AI 无法引用记录的营养值。

## 设计要点

### A. system prompt 增加「系统事实」段（parser / answers 共用）
在聊天与查询的 system prompt 中加一段简短的系统口径声明，至少覆盖：
- 食物库主食 canonical 为**熟重**（米饭/面条/馒头等匹配到的每 100g 值就是熟值）；
- 记录里的热量/营养由后端按库值 × 克数算出，是唯一真值；
- `is_estimated` 食物为 AI 估算兜底，可说明「这是估算值」，但**不得**在对话中另报一套不同的数字；
- 被问及某条**已记录**食物的热量/蛋白等 → 必须引用记录值（见 B），禁止重新估算；
- 被问及系统如何工作（生熟、算法、是否记住）→ 只按本段事实回答，不知道就说不知道，**严禁编造系统行为**。

### B. `RecordRef` 补齐宏量素
`services/memory.ts` 的 `RecordRef` 增加 `p`/`f`/`c`（四舍五入整数克，与 `DaySummary` 命名对齐），`buildMemoryPack` 从 food_record 透传。留意上下文体积（今日记录条数有限，增量可控）。

### C. 数据订正（一次性，prod 库）
把 2026-07-09 误造的「全麦欧包（熟的）」（`FoodStandard e8a640a2`）合并回「全麦欧包」（`8716c6e1`）：
- 该 FoodRecord（`cb259176`）的 food_id 指回 8716c6e1，重算该条 calories/protein/fat/carbs（280 kcal/100g × 50g），联动 daily_summary 重算；
- `UserFoodAlias` 中 canonical=全麦欧包 的 food_id 改回 8716c6e1；
- 删除 e8a640a2 条目。
- **在 prod 库操作，先备份相关行；只动这三处，不做批量清理。**

## 验收
1. 问「200克米饭多少热量」→ 回答基于 116 kcal/100g（≈232 kcal）并能说清是熟重口径；不再出现「系统按生重算」类说法。
2. 已记录某食物后追问其蛋白/热量 → 回答引用记录值（与 Today 页一致），不另报估值。
3. 问「你们系统米饭按生的还是熟的算」→ 按系统事实段回答，无编造。
4. `RecordRef` 带 p/f/c，`npm test` 通过。
5. `cd backend && npm run eval` 全绿（碰 AI prompt 必跑；起干净端口 `PORT=9309 npm run dev` + `EVAL_API_BASE=http://localhost:9309 npm run eval`，别打 :9300 常驻服务）。建议新增 eval 用例覆盖验收 1/2。
6. 数据订正后：outoftoken 7-09 晚餐卡欧包显示 140 kcal，daily_summary 对得上，「全麦欧包（熟的）」条目消失。
