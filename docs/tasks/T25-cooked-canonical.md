# T25 — 主食 canonical 默认取熟形（修生/熟热量虚高）

**状态**：✅完成  <!-- ⬜待办 / 🔄进行中 / ✅完成；任务验收通过后改这里 + 同步 docs/TASKS.md -->
> 实现落在三处：prompt 出明确熟形 + matcher 生/干条目降级 + 裁决层生熟枪毙（光改 prompt 不够，生重条目会经前缀代表值/trgm 漏出）。

**目标**：修主食热量虚高 ~2.5 倍——成分表主食多为生/干重（糙米348、面条/挂面350+），用户吃熟食却命中生重。方案 A：parse prompt 让 canonical 对主食默认取**熟形**。
**依赖**：T04 T24　**关注文档**：AI_PARSING_SPEC §3，FOOD_DB_SPEC

## 根因（实测）
- food_standard 主食几乎全是生/干重；只有大米有「米饭（蒸，代表值）116」熟条目。
- "米饭"命中熟条目对；"糙米"精确命中生米348（精确匹配，连 T24 裁决都走不到）。

## 做什么
- parse prompt：canonical 对**人吃熟的主食**默认取熟形——糙米→糙米饭、面条/挂面→熟面条/面条(煮)、燕麦→燕麦粥、面粉类(馒头/花卷)用成品名。给几个示例。
- 命中库里熟条目→对；无→走 matchFood 的 AI 估算（估熟食 ~对）。
- 不动数据/schema（方案 B 的打标+吸水系数换算留作后续，见记忆 food-db-raw-vs-cooked）。
- FOOD_DB_SPEC 补一句生/熟口径说明。

## 验收
- 「吃了200克糙米」/「一碗糙米饭」→ canonical=糙米饭 → 不再记成 348/100g（生米），落到熟食量级(~110-130)。
- 「一碗面条」→ 熟面条量级(~110-140)，不是 350(干面)。
- 回归：「米饭」仍命中米饭（蒸）116，不被带跑。
