# TEST_PLAN — 测试计划

> 讲怎么验证。每个任务的具体验收在对应 `docs/tasks/*.md`，本文件是分层总览。

## 1. 数据导入（食物库）
- 能量自检：导入时三大营养素反推能量，偏差 >25% 全部进 `review_flags.csv` 人工复核。
- 抽查：米饭、鸡蛋、鸡胸肉、牛奶、苹果 等高频食物能量值合理。
- 计数：`food_standard` 约 1677 条。

## 2. 计算引擎（单元测试）
- 已知身高体重年龄性别 → BMR/TDEE 与手算一致。
- 给定 food 行 + 克数 → kcal/三大营养素正确。
- 缺口/目标/剩余口径正确（含运动叠加）。
- 边界：营养字段 null 不崩。

## 3. AI 解析
- 样本集覆盖三种意图：record / query / chat，意图判对率统计。
- 双置信度：含糊输入（"整了点外卖"）能正确进中/低置信分支。
- 解析输出全部通过 zod；构造一次坏输出验证重试/兜底不崩。

## 4. 食物匹配
- 命中：精确名、别名各一例。
- 模糊：错别字/近似写法（"鸡胸肉"vs"鸡胸"）走 pg_trgm 命中。
- 兜底：生僻复合菜走 DeepSeek 估算并落库，二次输入变命中。

## 5. API（curl 流程）
- register → login → 带 token 访问受保护路由；无 token 401。
- PUT profile 返回正确 tdee/targets。
- chat/message：记录一餐入库 + 查询"还能吃多少"答得出 + 含糊输入返回 pending。
- pending/resolve 正确入库。
- daily/today、daily/range 数据正确。

## 6. 端到端一致性（最重要）
- 在 Chat 记一餐 → Today 的摄入/缺口随之更新 → History 当天出现该记录。
- 改/删某条 food_record → Today/History 同步，且对应 record_card 显示回填/"已删除"。
- **删 chat_message 不影响任何热量统计**（事实层 vs 展示层验证）。

## 7. 聊天持久化与保留
- 记录后切到 Today 再回 Chat，对话与卡片仍在。
- 换设备/重装后能拉回服务端聊天。
- 切换日期线程加载对应天对话。
- 本地"清除缓存"后能从服务端拉回。
- 保留策略：构造 366 天前的 chat_message，跑清理任务被删，而同日 food_record 仍在。

## 里程碑验收
- **M1（命令行心跳）**：`一碗牛肉面加个蛋` → 打印食物/克数/合计 kcal。
- **M2（后端全通）**：curl 跑完注册→onboarding→记录→查询→今日→历史 全流程。
